# 보고서 CAD 보강 검증 인계

브랜치 `docs/report-cad`, worktree `wt-rep2`에서 원고·웹 표시·정적 검사를 수정했다. 커밋·push·PR·index 변경·Chromium 실행은 수행하지 않았다. `cover_local.json`은 열지 않았다. 기존 PDF는 그대로이며 새 원고와 일치하지 않는다.

## 변경 파일

- `web/js/cad_page.js`, `cad_light.js`, `web/theme-light.css`: light 전용 `cadPage.select('all')` / `cadPage.showAll()`. 전 그룹 표시·불투명·자기 색, 추가 장치 다섯 기능 이름만 작은 라벨. 기본 쿼리 없는 화면의 실행 경로는 유지한다.
- `chapters/cad_workflow.html`, `cad_colors.html`, `cad_review.html`: SVG 제작 흐름, 전체 색·분해도, 기말 도면 3종·배선도·원본 summary 검토표.
- `chapters/01.html`~`35.html`, `summary/01.html`~`09.html`, `pages.json`: 연속 장·절 번호, 목차, 변경 쪽 번호와 요약 연결, light 이미지 참조.
- `build_v2.py`, `report.css`, 생성 HTML 두 파일: 표지 버전 문구 제거, 새 쪽 조립 및 스타일. 파일명·경로는 그대로 유지.
- `check_toc.py`, `check_static.py`, `numbers.json`, 검사 JSON·수치대조표: 제목·쪽·버전 문구·이미지·원본 수치 검사. `make_figs.py`의 기존 S4 재도식화 결과를 8쪽에 재사용한다.
- `README.md`, 이 문서: 현재 구성·검사·Claude 확인 목록.

## 새 쪽 구성

표지를 제외한 본문 번호다. 본문 38쪽, 표지 포함 39쪽. 요약본은 9쪽, 표지 포함 10쪽. 별도 부록 57쪽은 유지한다.

| 장 | 본문 쪽 |
|---|---|
| 1 요약 / 목차 | 1 / 2 |
| 2 과제 목표와 요구사항 | 3–4 |
| 3 중간 설계 요약 | 5–7 |
| 4 왜 HBM 적층인가 | 8–9 |
| 5 장비 고도화 | 10–16 |
| 6 디지털 트윈 | 17–19 |
| 7 시뮬레이션 결과 | 20–24 |
| 8 트러블슈팅과 개선 성과 | 25–32 |
| 9 한계와 향후 시험 | 33–35 |
| 10 결론 | 36 |
| 11 참고문헌 | 37–38 |

추가 CAD 14쪽은 Fusion Python → STEP → 그룹별 STL → GLB 제작 흐름이다. 실제 코드는 STEP·STL을 같은 Fusion 조립체에서 각각 출력하며 STEP 재입력 변환은 아니다. STL은 부품 바디를 10개 그룹으로 묶는다. 15쪽은 전체 색·분해도, 16쪽은 도면 3종·배선도와 summary 저장값이다. 기능 5종 / 신규 CAD 8개 / 전체 51개를 구분한다. 높이·질량은 참고값이다.

## 재검사 명령과 판정

```sh
node --test 'sim/test/*.test.js'
/Library/Frameworks/Python.framework/Versions/3.12/bin/python3 docs/report/v2/make_figs.py
python3 docs/report/v2/check_numbers.py
python3 docs/report/v2/build_v2.py --html-only
python3 docs/report/v2/check_toc.py --text-dir /tmp/report-cad-text
python3 docs/report/v2/check_static.py
grep -Ein '\bv2\b' /tmp/report-cad-text/*.txt
git diff --check
```

검사 수치는 `toc_check.json`, `number_check.json`, `static_check.json`을 따른다. 목차 검사는 11개 장·37개 절의 번호·본문 제목·쪽·요약본 연결을 대조한다. 버전 문구 검사에는 표지·머리말·꼬리말·설명·부록 표시 텍스트가 포함된다. 파일명·저장소 경로는 명시적 예외이며 스타일·스크립트도 표시 텍스트에서 제외한다. grep 출력 0줄·종료 코드 1이 기대값이다.

이번 실행 결과: Node 시험 184개 통과·실패 0, 목차 11장·37절 및 쪽 연결 통과, 표시 텍스트 버전 문구 0건, JSON 표시 대조 93회·고유 키 53개 통과, S1 별도 저장값 24개 일치, 그림 원본 SHA256 일치, Pretendard 그래프 재생성 완료, `git diff --check` 통과. 수동 숫자 문맥 304개는 별도 검토 대상이다.

`check_static.py`는 아직 없는 `cad_light_all.png`를 참조하는 두 곳(본문 15·19쪽)에서 실패한다. 대체 파일을 만들거나 기존 캡처를 이름만 바꾸지 않았다. 캡처 수령 후 위 검사를 재실행해야 한다. 저장 자세 간섭 0건은 전 스트로크 충돌·고온 조립성·배선 접근 통과가 아니다. 수동 숫자 문맥과 이미지 내부 치수는 자동 통과에 합산하지 않는다.

## Claude 캡처·PDF 확인

1. 웹 CAD `https://ycpark06.github.io/hbm-stacking-edu-sim/web/cad.html?theme=light`에 수정 자산이 반영된 환경을 연다. 3D 초기화 후 콘솔에서 `cadPage.showAll()` 또는 `cadPage.select('all')`, 필요하면 `cadPage.setViewOnly(true)`를 실행한다. 모든 그룹이 표시되고 불투명하며, 적층 척·리플로우 척·가압 충전 지그/플런저·디스펜서·NCF 트레이만 이름 라벨이 있는지 확인한다. 회전·확대 시 라벨 겹침·화면 밖 잘림도 확인한다.
2. 조립 상태에서 `media/stills/light/cad_light_all.png`를 캡처한다. 기존 `cad_light_exploded.png`는 전체 색 상태와 다섯 라벨 기준에 맞는지 확인하고 필요하면 분해 슬라이더 조절 후 재캡처한다. 분해 거리는 표시 설정이다.
3. 기본 쿼리 없는 CAD 화면, light 단일 선택, 숨긴 그룹 뒤 showAll, 분해·초기화·전체 색 재선택이 정상인지 확인한다. 공개 URL의 배포 상태는 이번 작업에서 확인하지 않았다.
4. 본문 8쪽 S4 막대는 `stage4_results.json` 저장값·sidecar와 대조한다. 본문 19쪽은 CAD 전체 색 + MR 리플로우, 요약본 3쪽은 TC, 4쪽은 MR 충전 light 캡처다. 흰 바탕·Pretendard·색 구분을 확인한다.
5. 새 14–16쪽의 흐름도 경로와 글자, CAD 라벨, 도면 축소본·배선도 판독성 및 표·footer 간격을 확인한다. 기말 도면 원본은 `stack_chuck.png`, `reflow_chuck.png`, `mold_jig.png`다. 원본에 포함된 수치·글꼴은 다시 그리지 않았으므로 확대 판독·폰트 확인 대상이다.
6. 본문 2쪽 목차 두 열, 모든 본문 절 번호의 줄바꿈, 기존 25쪽 온도 미달 사례와 20–24쪽 그래프, 요약본 3·4·6·7쪽 밀도를 확인한다.
7. `build_v2.py --pages-png /tmp/report-cad-pages --check-overflow`로 공개 PDF·PNG·render_check.json을 생성한다. 예상 PDF는 본보고서 39쪽, 요약본 10쪽이다. 이미지 로드·넘침·글꼴·쪽 번호 및 표시 텍스트 버전 문구 0건을 확인한다. 개인정보 표지는 별도 허용된 로컬 절차로 처리한다.
