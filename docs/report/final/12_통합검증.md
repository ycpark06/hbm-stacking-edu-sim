# 12. 통합 검증 (Integrated Verification)

**중간 대비 바뀐 점**

- 중간 통합 오차 예산과 요구 대응표를 기준점으로 유지했다.
- 기말 golden·전체 테스트·적층 시나리오 검증을 추가했다.
- 대표 장면과 민감도는 최신 모델 보정 결과를 사용했다.
- 소프트웨어 재현성·설계 계산·실물 검증의 범위를 구분했다.

**중간 기준점과 기말 판정의 구분.** 12.1~12.6절은 `calc/midterm/integration.json`과 중간 각 장의 계산·예산·절차 검증을 보존한 기준점이다. 계산 결과를 실측으로 취급하지 않는다. 원문 KPI·설계 목표 구분은 검증표에 따르며, 중간 18항목 집계는 기말 신규 목표의 집계가 아니다. 최신 적층 결과·실패·웹 검증은 12.7절 이후와 14장에 기록했다.

## 12.1 목적

PBL 7쪽은 KPI를 "시뮬레이션 및 데이터로 검증"하라고 하고, 11쪽 일정은 마지막 단계로 "통합 모의 검증"을 둔다. 이 장에서는 세 가지를 확인한다.

1. **정합 종합:** 5장에서 나눠 준 오차 예산 대신 6~10장의 실제 설계 결과를 넣어 다시 합산했을 때도 ±1 μm를 지키는가
2. **검증표:** 원문 KPI, 원문 요구, 설계 목표, 파생 요구 18개 항목의 최종 판정
3. **요구 충족:** PBL 3~11쪽의 요구가 보고서 어디에서 어떻게 다뤄졌는가

## 12.2 정합 종합: 설계 결과로 다시 합산

5장의 0.88 μm는 각 항목에 "이만큼 허용한다"고 나눠 준 예산의 합이었다. 이제 각 장의 계산 결과로 그 예산을 바꿔 넣는다. 결과가 없는 항목은 예산값을 그대로 쓴다. 두 경우로 나눠 계산했다.

- **대표:** 각 장의 기준 조건 결과
- **보수:** 각 장의 최악 조건 결과. 결과가 예산보다 작아도 근거가 약하면 예산값을 쓴다

**결과를 읽는 방법.**

## 12.6 한계

- **모의 검증이다.** 모든 결과는 계산과 시뮬레이션이다. 볼트 체결부의 유연성, 실제 가이드의 비반복 성분, 접착제의 비뉴턴 거동처럼 모델에 넣지 못한 것들이 있다. 8장의 4배 여유, 9장의 1.3~4배 여유는 이 불확실성의 몫이다.
- **검증하지 못한 항목:** 다이 미끄러짐(#8)과 바닥 진동 진폭(#9)은 계산 모델이 없어 예산값을 그대로 썼다. 평행도는 제작 후 측정한다.
- **장비를 만든다면 먼저 할 일:** ① 실습 4(KPI 검증)로 실제 3σ 측정, ② 접촉 미끄러짐 측정(건식 배치 전·후 오프셋 차), ③ 평행도 측정(13.5절), ④ 열드리프트 실측(정렬 후 5 s 동안 피듀셜 추적).

## 12.8 민감도와 펌웨어 비교

최신 민감도에서 기본 대비 판정 변경 셀 수는 툴 접촉 열저항 **8**, 척 접촉 열저항 **3**, MUF 입구 유효압력 **1** 순이다. 앞의 두 항목은 역산 추정값, 입구 압력은 가정값이다(`docs/stage4_model_update.md` 민감도 표, `scenario_results.json`) . 이는 정해진 사례에서 한 입력씩 range 끝점으로 바꾼 국소 분류 변화이며 전역 중요도·가정 신뢰도 순위가 아니다. 수치가 변해도 같은 불량 구간이면 셀 수는 그대로이고, 계산에 연결되지 않은 메타데이터는 변화가 없을 수 있다. 상세 한계는 15장 15.9절을 참조한다.

PC↔wasm 고정 입력 비교는 두 모드 각각 600입력, 출력 12열·총 1,200행(14,400값)을 대조한다. 최대 절대 차이 **8.119141e-6**, 허용치 `max(상대 1e-3, 절대 1e-4)`로 통과했다. 출력에는 서로 다른 단위와 상태 플래그가 섞이므로 이 최대값에 일괄적으로 N 또는 ℃를 붙이지 않는다. 출처는 `firmware/README.md` 검증 6, `firmware/test/test_wasm.mjs`이며 임시 복사본 `make test`, `make mcu`, `make wasm`, `make test-wasm`으로 확인했다. 이것은 같은 제어기의 실행 경로 일치 검증이며 물리 플랜트 정확도 검증이 아니다.

## 12.9 웹·브라우저·배포 확인 범위

`web/tools/check_hmi.mjs`는 JS 문법 29개·상대 의존성 39개·HTML 자산·vendor SHA256 검사를 통과했다. `wasm_check_node.mjs`의 고정 입력 1,000 tick도 실행했다(소프트웨어 확인 결과). `check_worker.mjs`도 S1~S5의 메시지·전체 이력·wasm SIL·완료를 확인했다. 이 검사는 DOM·3D 화면을 검사하지 않는다.

헤드리스 확인은 저장소 밖 임시 복사본에서 원래 `headless_check.sh`를 실행했으나 **Chrome 종료 상태 -6으로 실패**했다. 이번 원고 개정에서 실제 브라우저 화면·DOM 확인은 미완료이며 샌드박스 우회는 하지 않았다. Claude의 허용 환경에서 헤드리스·대화형 브라우저 재검증이 필요하다.

PLAN 12절에는 단계 4 웹 실행·3D·알람과 Pages 배포 완료가 기록되어 있고, `.github/workflows/pages.yml`은 자산 조립·업로드·배포 경로를 정의한다. README의 데모 주소는 `https://ycpark06.github.io/hbm-stacking-edu-sim/`이다. 이 원고의 배포 완료 표기는 그 저장소 기록을 근거로 하며, 배포 서버의 현재 상태나 이번 문서 개정의 재배포를 새로 확인했다는 뜻은 아니다. 브라우저/헤드리스 확인과 웹 구성의 상세는 16장 16.5절을 참조한다.
