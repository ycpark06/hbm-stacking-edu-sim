# 1. 문제 정의 (Problem Definition)

**중간 대비 바뀐 점**

- 단일 다이 부착에서 HBM 방식 다단 적층으로 과제 범위를 넓혔다.
- TC-NCF / MR-MUF 원리 비교 교육 장비로 정의하고 우열 판정과 구분했다.
- 실물 제작 대신 웹 디지털 트윈으로 구동하며 기존 구조·계산을 계승한다.
- 기말 PBL 요구와 15~17장 연결, 모델 검증과 실물 시험의 경계를 추가했다.

## 1.1 배경: 접합 공정의 비중이 커지고 있다

첨단 패키징에서는 칩을 붙이고 잇는 공정이 성능을 좌우한다. HBM은 얇은 DRAM 다이를 12~16층 쌓고(0917 공정 강의 13쪽), 칩렛은 서로 다른 다이를 한 기판 위에 붙인다(1008 2.5D·3D 강의 76~77쪽). 이 과정에서 접합 장비가 하는 일은 단순하다. 다이를 집고, 맞추고, 누르고, 데운다. 그러나 결과는 온도·하중·시간·접착제 양에 따라 크게 달라진다. 같은 장비에서 같은 다이를 붙여도 조건을 바꾸면 접착층 두께, 보이드, 휨, 크랙이 달라진다(4장).

다이 본딩은 이 접합 공정 가운데 가장 기본이 되는 단계다. 콜렛으로 다이를 집어 접착제 위에 놓고 힘·시간·온도를 조절해 붙인다(0917 공정 강의 34~40쪽). 열압착(TCB)은 같은 동작에 높은 온도와 큰 하중을 더한 것으로, HBM 적층의 TC-NCF 공정이 그 예다(1008 강의 95~97쪽). 그래서 다이 본딩을 이해하면 첨단 접합 공정의 기본 물리를 이해할 수 있다.

## 1.2 문제: 양산 장비로는 공정 물리를 배울 수 없다

PBL 강의자료 3쪽은 산업용 양산 장비의 두 가지 한계를 지적한다.

| 한계 | 원문 (PBL 3쪽) | 학생에게 생기는 문제 |
|---|---|---|
| 블랙박스 | "수십억 원대의 대형 차폐형 설비로 내부 접합 거동이나 유동 현상을 실시간 관찰하기 불가능" | 접착제가 어떻게 퍼지고, 보이드가 어떻게 생기는지 볼 수 없다. 결과만 보고 원인을 추측해야 한다 |
| 고정 레시피 | "생산 수율 보장을 위해 고정된 레시피로만 운용되어 학생들의 파라미터 튜닝 및 불량 메커니즘 분석이 제한" | 조건을 바꿔 불량을 일부러 만들어 볼 수 없다. 변수와 결과의 관계를 실험으로 확인할 수 없다 |

여기에 현실적인 제약이 더해진다. 양산 장비는 클린룸 공간과 큰 예산이 필요하고, 학생이 조작하다 고장 나면 생산이 멈춘다. 상용 R&D 본더(Finetech, Tresky 등, PBL 6쪽)는 실습실에 둘 수 있는 크기다(사양 비교는 3장 3.1절). 그러나 완성된 제품이라서, 학생이 제어 루프나 비전 알고리즘을 직접 설계하고 고쳐 보는 대상은 아니다.

## 1.3 목표: 두 적층 공정의 원리를 비교하는 교육 장비

PBL 3쪽이 제시한 교육용 장비의 강점을 설계 목표로 바꾸면 세 가지다.

1. **보이게 한다 (공정 가시화).** 접합이 일어나는 동안 내부를 직접 본다. 원문은 "광학 현미경 및 투명 챔버"로 "언더필 유동 과정을 직접 시각적으로 관찰"하라고 한다.
2. **바꿀 수 있게 한다 (파라미터 가변).** 온도·압력·속도를 바꿔 "미접합, 보이드, 휨 등 실제 산업 불량 사례를 유도하고 분석"한다. 5쪽은 온도·유지 시간·하중·도포량의 네 변수를 제시한다.
3. **수치로 검증한다 (정량 KPI).** 7쪽은 "단순한 아이디어 도출에 그치지 않고, 산업계 스펙에 준하는 공학적 목표치(KPI)를 설정하여 시뮬레이션 및 데이터로 검증"하라고 한다.

기말 과제에서도 위 교육 목적과 원문 KPI를 유지한다. 세 번째 목표가 설계를 어렵게 만든다. 관찰과 조건 변경만이라면 현미경과 핫플레이트로도 된다. 그러나 ±1 μm 정합, 400 ℃ 펄스 가열, 50 N 하중을 600 mm 안의 장비에서 동시에 지켜야 한다. 400 ℃ 열원 옆에서 1 μm를 지키려면 열팽창을 계산해야 하고(7장), 50 N을 눌러도 헤드가 옆으로 밀리지 않아야 한다(8장). 이 장비는 "보여 주는 장비"이면서 동시에 "산업 수준으로 정밀한 장비"여야 한다.

## 1.4 기말 PBL 요구와 설계 범위

중간의 단일 다이 부착 장비를 **HBM 방식 다단 적층 본더**로 고도화한다. TC-NCF는 필름을 미리 붙인 다이를 층마다 열압착하고, MR-MUF는 각 층을 임시 고정한 뒤 전체 리플로우와 수지 충전을 수행한다. 학생은 같은 시편에서 열 이력·정렬·휨·충전·사이클 시간의 차이를 비교한다. **두 공정의 우열을 판정하는 장비가 아니다.** 업체의 공개 주장은 출처와 함께 표시하는 관찰 항목이며 계산 입력이나 합격 기준으로 쓰지 않는다(근거: `docs/PLAN.md` 1·5·7절, `docs/requirements.md` 5~7절).

| 구분 | 기말 범위 | 근거 파일 |
|---|---|---|
| 장비 | 고정 헤드 + 이동 기판, 조동·미동 정렬 구조를 유지하고 적층·리플로우·가압 충전 치구 추가 | `docs/PLAN.md` 8절, `calc/hardware/README.md` |
| 공정 | TC-NCF / MR-MUF 선택, 층별 정렬·가열·가압 및 후공정 비교 | `docs/requirements.md` 3~6절 |
| 시편 | 5×5 mm 더미 다이, 기본 100 μm·비교 50 μm, 2/4/8/12단 (설계 목표) | `docs/requirements.md` 3절 |
| 구동 | 실물 없이 시뮬레이션 디지털 트윈으로 실행, 웹 HMI와 3D 뷰에서 결과 재생 | `README.md` 2절 |
| 계승 | 다이본더 구조, RSS 오차 예산, 구동부, 펄스 히터·단열·냉각의 계산 | `docs/report/midterm/03_시스템구성.md`~`07_열설계.md` |
| 범위 밖 | 실물 제작·센서 보정·보드 bring-up·양산 수율 인증 | `firmware/README.md`, `calc/hardware/README.md` |

기말 안내의 요구는 하드웨어 설계와 디지털 트윈, 제어 안정성·UI/UX·에러 처리의 고도화, 아키텍처와 트러블슈팅·개선 성과의 기술 보고, 도면·소스·바이너리·시뮬레이션 산출물 및 버전 관리 이력이다. 대응표는 `docs/PLAN.md` 2·4·8·9·12절을 따른다. 실물 없이 구동한다는 범위에서 시뮬레이션 통과를 실장비 시험 완료로 표현하지 않는다.

**KPI 해석 원칙.** 원문 KPI·원문 요구와 설계 목표·설계값·문헌값·역산 추정값·가정값·관찰 항목·참고값을 구분한다(2장). 업체가 공개하지 않은 세부 공정 조건은 교육용 가정이며, 문헌의 개별 값이나 확정 설계값과 함께 `sim/params.json`의 구분·근거를 유지한다.

## 1.5 접근 방법과 도구

| 단계 | 방법 | 도구 |
|---|---|---|
| 요구 정의 | PBL 원문 해석, 상용 R&D 본더 조사 | 문헌·제조사 자료 |
| 오차 배분 | 9개 오차원의 RSS 합산, 몬테카를로 검증 | Python |
| 계산·해석 | 중간 계산을 보존하고 적층 열 사슬·유동·휨·자기정렬·하드웨어 손계산 추가 | Python, JS |
| 디지털 트윈 | 공통 C 제어기 SIL, 웹 레시피·알람·그래프·3D 재생 | C, wasm, JS |
| 형상·도면 | 사양 파일에서 Fusion 스크립트를 자동 생성해 조립 모델 작성, 부품 도면 3장 | Autodesk Fusion, Python |
| 통합 검증 | 모든 결과를 KPI·설계 목표 대비 판정표로 취합 | 검증표 (12장) |

중간 계산은 `calc/midterm/`에 보존하고, 공정 입력은 `sim/params.json`, 신규 하드웨어 치수·물성은 `cad/stacker/spec_stacker.py`와 `calc/hardware/hw_params.json`을 따른다. 계산 결과와 출처를 함께 옮기며 보고서 작성 중 새 수치를 만들지 않는다. 모델의 가정과 실물 확인 항목도 함께 남긴다(`docs/model_inventory.md`, `calc/hardware/README.md`).
