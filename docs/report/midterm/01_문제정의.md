# 1. 문제 정의 (Problem Definition)

## 1.1 배경: 접합 공정의 비중이 커지고 있다

첨단 패키징에서는 칩을 붙이고 잇는 공정이 성능을 좌우한다. HBM은 얇은 DRAM 다이를 12~16층 쌓고(0917 공정 강의 13쪽), 칩렛은 서로 다른 다이를 한 기판 위에 붙인다(1008 2.5D·3D 강의 76~77쪽). 이 과정에서 접합 장비가 하는 일은 단순하다. 다이를 집고, 맞추고, 누르고, 데운다. 그러나 결과는 온도·하중·시간·접착제 양에 따라 크게 달라진다. 같은 장비에서 같은 다이를 붙여도 조건을 바꾸면 접착층 두께, 보이드, 휨, 크랙이 달라진다(4장).

다이 본딩은 이 접합 공정 가운데 가장 기본이 되는 단계다. 콜렛으로 다이를 집어 접착제 위에 놓고 힘·시간·온도를 조절해 붙인다(0917 공정 강의 34~40쪽). 열압착(TCB)은 같은 동작에 높은 온도와 큰 하중을 더한 것으로, HBM 적층의 TC-NCF 공정이 그 예다(1008 강의 95~97쪽). 그래서 다이 본딩을 이해하면 첨단 접합 공정의 기본 물리를 이해할 수 있다.

## 1.2 문제: 양산 장비로는 공정 물리를 배울 수 없다

PBL 강의자료 3쪽은 산업용 양산 장비의 두 가지 한계를 지적한다.

| 한계 | 원문 (PBL 3쪽) | 학생에게 생기는 문제 |
|---|---|---|
| 블랙박스 | "수십억 원대의 대형 차폐형 설비로 내부 접합 거동이나 유동 현상을 실시간 관찰하기 불가능" | 접착제가 어떻게 퍼지고, 보이드가 어떻게 생기는지 볼 수 없다. 결과만 보고 원인을 추측해야 한다 |
| 고정 레시피 | "생산 수율 보장을 위해 고정된 레시피로만 운용되어 학생들의 파라미터 튜닝 및 불량 메커니즘 분석이 제한" | 조건을 바꿔 불량을 일부러 만들어 볼 수 없다. 변수와 결과의 관계를 실험으로 확인할 수 없다 |

여기에 현실적인 제약이 더해진다. 양산 장비는 클린룸 공간과 큰 예산이 필요하고, 학생이 조작하다 고장 나면 생산이 멈춘다. 상용 R&D 본더(Finetech, Tresky 등, PBL 6쪽)는 실습실에 둘 수 있는 크기다(사양 비교는 3.1절). 그러나 완성된 제품이라서, 학생이 제어 루프나 비전 알고리즘을 직접 설계하고 고쳐 보는 대상은 아니다.

## 1.3 목표: 교육용 데스크톱 다이본더

PBL 3쪽이 제시한 교육용 장비의 강점을 설계 목표로 바꾸면 세 가지다.

1. **보이게 한다 (공정 가시화).** 접합이 일어나는 동안 내부를 직접 본다. 원문은 "광학 현미경 및 투명 챔버"로 "언더필 유동 과정을 직접 시각적으로 관찰"하라고 한다.
2. **바꿀 수 있게 한다 (파라미터 가변).** 온도·압력·속도를 바꿔 "미접합, 보이드, 휨 등 실제 산업 불량 사례를 유도하고 분석"한다. 5쪽은 온도·유지 시간·하중·도포량의 네 변수를 제시한다.
3. **수치로 검증한다 (정량 KPI).** 7쪽은 "단순한 아이디어 도출에 그치지 않고, 산업계 스펙에 준하는 공학적 목표치(KPI)를 설정하여 시뮬레이션 및 데이터로 검증"하라고 한다.

세 번째 목표가 설계를 어렵게 만든다. 관찰과 조건 변경만이라면 현미경과 핫플레이트로도 된다. 그러나 ±1 μm 정합, 400 ℃ 펄스 가열, 50 N 하중을 600 mm 안의 장비에서 동시에 지켜야 한다. 400 ℃ 열원 옆에서 1 μm를 지키려면 열팽창을 계산해야 하고(7장), 50 N을 눌러도 헤드가 옆으로 밀리지 않아야 한다(8장). 이 장비는 "보여 주는 장비"이면서 동시에 "산업 수준으로 정밀한 장비"여야 한다.

## 1.4 설계 범위

| 구분 | 범위 |
|---|---|
| 장비 | 교육용 데스크톱 다이본더 1대 (고정 헤드 + 이동 기판 구조, 3장) |
| 기본 공정 | 에폭시(은 페이스트) 다이 부착: PBL 5쪽의 네 변수 실습 |
| 확장 공정 | Cu pillar 열압착(TCB), NCF: 400 ℃·50 N KPI의 근거 (4.9절) |
| 운전 모드 | 수동(정렬 원리 체험), 자동(DoE), 관찰(유리 기판 + 하부 카메라), KPI 검증 |
| 설계 산출물 | 요구사항·KPI, 시스템 구성, 공정 물리, 오차 예산, 구동부, 열, 구조·진동, 비전, 제어·회로, CAD·도면, 통합 검증, 교육·안전 |
| 범위 밖 | 실제 제작과 시험. 이 보고서는 계산과 시뮬레이션으로 검증한다(PBL 11쪽 "통합 모의 검증") |

**KPI 해석 원칙.** KPI는 PBL 강의자료에 적힌 정보만으로 해석한다. 원문에 없는 수치는 "설계 목표" 또는 "파생 요구"로 따로 표시하고 근거를 밝힌다. 질량·높이처럼 원문에 기준이 없는 값은 판정하지 않는 참고값으로 둔다(2장).

## 1.5 접근 방법과 도구

| 단계 | 방법 | 도구 |
|---|---|---|
| 요구 정의 | PBL 원문 해석, 상용 R&D 본더 조사 | 문헌·제조사 자료 |
| 오차 배분 | 9개 오차원의 RSS 합산, 몬테카를로 검증 | Python |
| 계산·해석 | 구동부 토크, 열 집중정수 모델, 3차원 FEA(정적·모달), 비전 합성 영상 시험, 제어 시뮬레이션 | Python (NumPy, SciPy, OpenCV) |
| 형상·도면 | 사양 파일에서 Fusion 스크립트를 자동 생성해 조립 모델 작성, 부품 도면 3장 | Autodesk Fusion, Python |
| 통합 검증 | 모든 결과를 KPI·설계 목표 대비 판정표로 취합 | 검증표 (12장) |

모든 치수와 계산 결과는 하나의 사양 파일과 계산 스크립트에 연결했다. 한 장에서 설계를 바꾸면(예: 7장의 히터 크기, 8장의 프레임 구조) 모델과 다른 장의 계산을 같은 값으로 다시 돌렸다.
