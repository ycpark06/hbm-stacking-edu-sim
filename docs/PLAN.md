# 작업 계획서 — 교육용 HBM 적층 본더 (TC-NCF / MR-MUF 비교 시뮬레이터)

- 과목: UNIST MSE489 첨단패키징기술, 기말고사 대체 PBL 과제
- 근거 자료: 기말 과제 안내 슬라이드(2026-11-19, 18쪽), 원 PBL 강의자료(11쪽), 중간 과제 설계 보고서(60쪽)
- 작성: 2026-11-25 · 상태: 승인됨 (변경 시 이 문서를 먼저 고친다)

---

## 1. 과제 정의

| 항목 | 내용 |
|---|---|
| 출발점 | 중간 과제의 **교육용 데스크톱 다이본더** (에폭시 다이 부착 + Cu pillar 열압착 확장, ±1 μm 듀얼 비전 정렬, 400 ℃ 펄스 히터, 하중 1 ms / 온도 10 ms PI 제어) |
| 고도화 방향 | 단일 다이 본딩 → **다단 적층(HBM 방식) 본더**. 한 장비에서 **TC-NCF 모드**와 **MR-MUF 모드**를 골라 두 공정의 메커니즘 차이를 비교한다 |
| 구동 방식 | 실물 제작 없이 **시뮬레이션(디지털 트윈)** 으로 구동한다. 웹 페이지(GitHub Pages)로 시연한다 |
| 장비 성격 | 어느 공정이 우수한지 판정하는 장비가 아니다. 학생이 두 공정의 **원리 차이**를 체험하는 교육 장비다 |

### 1.1 두 공정의 차이 (공개 자료 기준)

| 단계 | TC-NCF 모드 (삼성전자 방식) | MR-MUF 모드 (SK하이닉스 방식) |
|---|---|---|
| 다이 준비 | 다이 밑면에 NCF(비전도성 접착 필름) 부착 | 필름 없음 |
| 정렬 | 듀얼 비전 ±1 μm (공통) | 같음 |
| 적층 | 층마다 열 + 하중을 수 초간 가해 바로 접합 | 층마다 순간 가열로 임시 고정만 |
| 접합 완성 | 적층 단계에서 끝남 | 전체를 한 번에 리플로우 |
| 틈 채우기 | 필름이 이미 채우고 있음 | 액상 수지를 칩 사이에 모세관으로 충전 |

- 강의 근거: 0917 공정 84~85쪽(HBM 몰딩, MR-MUF, 10 μm 이하 간격의 보이드 위험), 1008 2.5D·3D 95~97쪽(TC-NCF, 250~300 ℃, 층별 가압 프로파일), 1001 플립칩 40쪽(리플로우 프로파일, 자기정렬).
- 공개 자료: SK하이닉스 뉴스룸 MR-MUF 기사(https://news.skhynix.com/en/?p=1917), 삼성전자 HBM3E 페이지(https://semiconductor.samsung.com/dram/hbm/hbm3e/).
- 두 회사 모두 온도·압력·시간 같은 세부 조건은 공개하지 않았다. 시뮬레이션의 공정 조건은 모두 **가정값**이다(5절).

## 4. 고도화 항목

### 4.1 제어 안정성
- 층별 하중·온도 프로파일 실행
  - TC-NCF: 층마다 승온 → 가압 유지 → 냉각
  - MR-MUF: 층마다 순간 가열(임시 고정) → 전체 리플로우 프로파일
- 중간 보고서 10장의 하중 1 ms PI, 온도 10 ms PI 루프를 **펌웨어 C 코드**로 구현한다(6절).
- 프로파일 추종 오차를 기록하고 그래프로 보여 준다.

### 4.2 UI/UX (웹 HMI)
- 모드 선택 (TC-NCF / MR-MUF), 레시피 입력 (층 수, 다이 두께, 온도, 하중, 시간, 수지량)
- 실시간 그래프: 온도, 하중, 휨, 충전율
- 3D 장비 뷰 (헤드 하강, 층 적층 애니메이션)
- 두 모드 결과 비교 화면

### 4.3 기능 완성도·에러 처리
| 알람 | 조건 (설계 목표 기준) | 동작 |
|---|---|---|
| 과하중 | 소프트웨어 한계 초과 | 감속·정지, 하드웨어 차단 모사 |
| 과온 | 소프트웨어 한계 초과 | 히터 차단 |
| 층간 정렬 오차 | 설계 목표 초과 | 재정렬, 반복 실패 시 정지 |
| 휨 한도 초과 | 층별 휨 설계 목표 초과 | 적층 중단 |
| 미충전·보이드율 초과 | 충전율·보이드율 설계 목표 초과 | 경고, 결과 표시 |

- 알람 한계값은 중간 보고서 3.5절 안전 계층(52 N / 410 ℃ 경고, 55 N / 420 ℃ 하드웨어 차단)을 이어 쓴다.

### 4.4 비전 정렬 시뮬레이션
- 층마다 가상 피듀셜 영상을 만든다(노이즈, 회전, 위치 오차 포함).
- 브라우저에서 NCC 검출 → 서브픽셀 보간 → 아핀 보정 → 정렬 지령 과정을 실행하고 화면에 보여 준다.
- 중간 보고서 9장의 알고리즘과 결과(0.009~0.031 px, 폐루프 3σ 0.09 μm)를 기준으로 삼는다.

## 5. 시뮬레이션 모델

| 모델 | 출처 (중간 보고서) | 비교 포인트 |
|---|---|---|
| 층별 열 이력 (1차원 집중정수) | 7장 | TC-NCF는 아래층이 N회 재가열, MR-MUF는 리플로우 1회 |
| 하중·온도 PI 응답 | 10장 → 펌웨어 | 프로파일 추종 |
| 비전 정렬 + 자기정렬 | 9장, 4.9절 | TC-NCF는 정렬 오차가 남음. MR-MUF는 리플로우 때 일부 보정 (임시 고정 영향은 가정 변수) |
| 휨 누적 (티모셴코 식) | 4.8절 | 층 수와 다이 두께에 따른 누적 |
| NCF 스퀴즈 유동 | 4.3절 | 필름이 밀려 나오는 양, 갇힌 보이드 |
| MUF 모세관 충전 (Washburn 식) | 13장 | 충전 시간, 미충전 |
| 사이클 시간 | 신규 | 처리량 |

**가정값 표기 원칙**
- 공정 조건은 강의 수치를 우선 쓴다: TC-NCF 250~300 ℃(1008 96쪽), 리플로우 피크 240~260 ℃·SAC 녹는점 약 217 ℃(1001 40쪽).
- 강의에 없는 재료 물성(NCF·EMC 점도, 표면장력, 접촉각 등)은 문헌값이나 가정값으로 두고, 출처나 "가정"을 함께 적는다.
- 모든 가정값은 `sim/params.json` 한 곳에 모으고, 웹 화면과 보고서에서 같은 파일을 참조한다.

**모델 일치 확인**
- Python 원본(`calc/`)과 JS 이식본(`sim/`)이 같은 입력에서 같은 결과를 내는지 테스트로 확인한다.

## 6. 펌웨어 구조

### 6.1 펌웨어가 하는 일
장비 안의 실시간 제어기(MCU)에서 돌아가는 프로그램이다.
- 센서 읽기: 로드셀(하중), 열전대(온도), 엔코더(위치)
- 제어 계산: 하중 PI (1 ms), 온도 PI (10 ms)
- 구동기 출력: Z 서보 지령, 히터 PWM
- 보호: 과하중·과온 인터락
- 비전 처리는 상위 PC(웹)가 맡는다(중간 보고서 3.5절 구조).

### 6.2 한 벌의 코드, 두 개의 빌드 (SIL 검증)
```
firmware/src/*.c  (제어 로직 1벌)
   ├─ MCU 빌드 (arm-none-eabi-gcc)  → firmware/build/controller.bin   … 실제 보드용 산출물
   └─ 웹 빌드  (emscripten)         → firmware/build/controller.wasm  … 웹 시뮬레이터가 실행
```
- 웹 시뮬레이터는 플랜트(열·하중 물리 모델)를 JS로 계산하고, 제어기는 wasm으로 실행한다.
- 시뮬레이터에서 검증한 제어기가 곧 실제 펌웨어라는 점을 보여 준다.
- 대상 MCU 계열은 2단계에서 정한다. 중간 보고서 10장의 회로 구성과 맞춘다.
- 하드웨어 의존 부분(ADC 읽기, PWM 출력)은 얇은 계층(HAL)으로 분리해 두 빌드가 바꿔 끼울 수 있게 한다.

## 8. 하드웨어 보완

### 8.1 CAD 부품 추가 (Fusion, 중간 모델 43부품에 추가)
- 적층용 척과 다단 더미 다이 시편

- NCF 다이 트레이 (필름을 미리 붙인 다이 공급)
- 층간 충전을 하부에서 관찰하는 광로

### 8.2 출력 파일
| 파일 | 용도 | 저장 방식 |
|---|---|---|
| STEP | 원본 보관 | Git LFS 가능 |
| GLB | 웹 3D 표시 (경량화, 부품 이름 유지) | **일반 커밋** (Pages는 LFS 파일을 제대로 서비스하지 못함) |
| 2D 제작 도면 (PDF) | 신규 부품: 적층 척, 리플로우 척, 디스펜서 브래킷 등. 공차·기하공차·조도·재질 포함 | 일반 커밋 |

- Fusion 스크립트 방식(중간 과제의 `DieBonderModel.py`)을 이어 쓴다.
- GLB 변환: Fusion에서 OBJ/FBX로 내보낸 뒤 Blender 등으로 GLB 변환, 작은 부품 제거·메시 단순화.

### 8.3 배선도
- 중간 보고서 10장의 회로 구성도를 정식 배선도로 만든다.
- 포함: MCU, 로드셀 ADC, 열전대 증폭기, 서보 드라이버, 히터 MOSFET, 리플로우 척 히터, 인터락 회로, 비상정지.

### 8.4 신규 부품 계산 (PBL 7쪽 필수 계산)
- 리플로우 척 히터 용량과 승온 속도 (리플로우 프로파일 추종 가능 여부)
- 적층 하중 경로 (층이 쌓일 때 하중이 지나가는 경로와 강성)
- 적층 구조의 열팽창 (다층 휨, 척·헤드 열변형)
- 계산은 Python으로 `calc/`에 추가하고 결과는 JSON으로 저장한다.

## 9. 교육·안전

### 9.1 실습 시나리오 (실습 매뉴얼)
| 실습 | 방법 | 학생이 확인하는 것 |
|---|---|---|
| A. 열 이력 비교 | 같은 층 수로 두 모드를 실행 | 아래층이 받는 열 횟수와 최고 온도 |
| B. 층 수 영향 | 모드는 고정하고 층 수만 2 → 4 → 8로 변경 | 휨 누적, 사이클 시간 |
| C. 정렬과 자기정렬 | 초기 정렬 오차를 일부러 주고 실행 | TC-NCF는 오차가 남고 MR-MUF는 일부 보정됨 |
| D. 보이드 원인 비교 | 필름 두께, 수지량, 간격을 변경 | 스퀴즈 유동 보이드와 모세관 미충전의 차이 |
| E. 알람 대응 | 한계를 넘는 레시피 입력 | 인터락 동작과 복구 절차 |

### 9.2 안전 항목 추가
- 리플로우 척 고온: 경고등, 냉각 전 접근 금지
- 수지 흄: 배기 후드
- 인터락 동작 확인 절차 (중간 보고서 13장에 추가)

## 11. Git 작업 흐름

### 11.1 태그

- `v2.0-final`: 최종 제출 상태

### 11.2 브랜치
| 브랜치 | 단계 |
|---|---|
| `feat/repo-setup` | 1 |
| `feat/firmware` | 2 |
| `feat/thermal-history`, `feat/tcncf-mode`, `feat/mrmuf-mode` | 3 |

### 11.3 커밋
- 기능 단위로 작게 커밋한다.
- 접두어: `feat:`, `fix:`, `docs:`, `refactor:`, `test:`, `cad:`

### 11.4 PR과 리뷰
- 모든 브랜치는 PR로 `main`에 병합한다. `main`에 직접 커밋하지 않는다.
- PR 템플릿 리뷰 체크리스트:
  - [ ] 변경 내용 요약
  - [ ] 테스트·확인 결과 (그래프, 수치, 스크린샷)
  - [ ] 원문 KPI와 설계 목표·가정값을 구분해 표기했는가
  - [ ] 관련 Issue 번호
  - [ ] 리뷰 의견과 반영 내용

### 11.5 Issue
- 라벨: `bug`, `model`, `firmware`, `ui`, `cad`, `docs`
- 기록 순서: 증상 → 원인 분석 → 해결 → 결과
- 해결한 Issue는 README 트러블슈팅 로그에 한 줄로 반영한다. 보고서 "트러블슈팅·개선 성과" 장의 재료가 된다.

## 13. 발표 구성 (단계 8)

**형식:** 짧은 슬라이드 + 웹사이트 라이브 시연

| 순서 | 내용 | 형식 |
|---|---|---|
| 1 | 배경: 중간 다이본더 → HBM 적층으로 고도화한 이유 | 슬라이드 |
| 2 | 장비 구조: 두 모드, 펌웨어·시뮬레이터 구조 | 슬라이드 |
| 3 | 개선 성과 요약 (`v1.0-midterm` → `v2.0-final`) | 슬라이드 |
| 4 | 모드 선택 → 적층 실행 (3D 뷰, 실시간 그래프) | 웹 시연 |
| 5 | 두 모드 결과 비교 (열 이력, 휨, 보이드, 사이클 시간) | 웹 시연 |
| 6 | 알람 발생과 처리 (과하중 또는 휨 한도 초과) | 웹 시연 |
| 7 | GitHub 이력 (브랜치, PR, Issue, 트러블슈팅 로그) | 웹 시연 |

- 슬라이드는 최소 분량으로 만들고, 설명의 중심은 실제 웹사이트에 둔다.
- 네트워크 문제에 대비해 로컬 실행본(`web/`을 로컬 서버로 실행)을 함께 준비한다.
